## 1. 产品定位（待审计确认）

Journal = 个人每日日志 + 打卡 + TODO + AI 辅助的**窄侧栏工具**。核心价值：低摩擦记录 + 一目了然的状态回顾。审计主线问题：**首屏是否把「记录与回顾」放在最优先位置**（当前实测：次要面板占满首屏，主工作区在折叠线下 —— 反例）。

## 2. 硬标准（可直接判定的可执行标准）

### 可访问性（WCAG 2.2）
| 准则 | 可执行标准 |
|---|---|
| 1.4.3 对比度(AA) | 正文/背景 ≥4.5:1；大号文本 ≥3:1 |
| 1.4.11 非文本对比 | UI 控件边界/状态 ≥3:1（对相邻色） |
| 1.4.1 颜色非唯一信息 | 状态不只靠颜色（热力图绿/灰需辅以文本/图案） |
| 2.1 键盘可达 | 所有交互可 Tab 达、可 Enter/Space 触发；焦点可见 |
| 2.4.3 焦点顺序 | Tab 顺序符合视觉顺序 |
| 2.4.7 焦点可见 | 焦点环清晰（≥2px、对比 ≥3:1） |
| 1.4.13 悬停/焦点内容 | hover/focus 弹出物不挡操作、可键盘关闭 |
| 3.2.2 输入一致性 | 表单提交不意外跳转 |
| 4.1.2 名称/角色/值 | 控件有 aria-label / 角色正确 |
| 2.3.1 闪烁 | 无 >3 次/秒闪烁（动画限制） |
| prefers-reduced-motion | 提供降级（当前产品 **缺失**，审计必项） |

### 动效（Material Motion 标准）
- 典型时长：150–200ms（微交互）、200–300ms（元素变换/视图切换）、300–500ms（大型过渡/全屏）。
- 缓动：入场 ease-out，出场 ease-in；强调注意用长时 + 弹性应克制。
- `prefers-reduced-motion: reduce` 下所有动画/过渡归零或最小化。

### 窄侧栏（Chrome side panel，宽度 320–500+ 可拖）
- 内容应按宽度分层：核心操作永远可达（header 固定）；二级内容可折叠（渐进披露）。
- 断点建议：<360 单列紧凑；360–440 标准；>440 允许两列信息流。
- 触控目标 ≥32px（密集工具可 28px 底线，需平衡）。

## 3. 状态设计（可执行标准）
- **空状态**：永远有「为什么空 + 下一步动作」，不得只显示空列表（当前「没有符合条件的卡片」文案待审）。
- **加载**：<300ms 无骨架直接渲染；300ms–1s 骨架屏；>1s 骨架 + 进度提示。
- **错误**：就地提示 + 可恢复动作（重试），不打断主流程（Toast 停留 3–5s 可关闭）。
- **成功反馈**：乐观更新优先；关键写入给轻量确认（check/toast）。
- **热力图**（GitHub 风格）：色阶 0→max 至少 4 档可分辨；当前默认空格 #ebedf0 与填充 #4caf50 对比需核查。

## 4. 图标策略（审计判定项）
- 功能图标（设置/视图/操作）应使用统一 SVG 图标集（当前全 emoji，跨平台不一致、无 hover/focus 态）。
- 情感/氛围用 emoji（保留 Twitter 系质感，项目风格要求）。
- 规则：**功能 = SVG，情感 = emoji**；icon 尺寸网格（16/20/24）与 stroke 宽度统一。

## 5. 信息架构与密度（审计判定项）
- 首要任务（记录/查看今日）放首屏可达区；次要面板可折叠。
- 渐进披露：高级功能（模板/命名视图/Skill）默认收起。
- 密度：密集工具行高 32–40px 为宜；数据密集视图（时间线）允许 24–32px。

## 6. 常见反模式清单（审计对照）
- 反模式1：次要内容占首屏、主内容折叠线下（**当前存在**）
- 反模式2：空状态只说「无数据」不给行动
- 反模式3：状态仅用颜色传达（热力图/进度）
- 反模式4：hover 才出现的操作在窄栏/触屏不可达
- 反模式5：信息重复（计数 badge 与空状态文案并存）
- 反模式6：无焦点管理导致 Tab 丢失（无 tabindex 结构）
- 反模式7：硬编码样式散落导致暗色/主题不一致（当前 79 处 hex）
- 反模式8：动效无 reduced-motion 降级（当前缺失）
