# 卡片编辑器弹窗（新建/编辑）样式与交互重做

## Goal

修复「＋ 新卡片 / 编辑卡片」弹窗在**真实 Chrome 侧栏（360–500px）**下样式拥挤、交互糟糕的问题，使其符合已确立的设计系统（.trellis/spec/frontend/design-system.md），达到窄栏友好、层级清晰、可键盘操作的交付质量。

## Background / Confirmed Facts（2026-09-28 实测）

真实渲染证据（dev-loop probe，360/400/500px 截图已存 `editor-*.png` / `editor-task-*.png`）：

1. **状态分段控件（.status-seg）挤压**：4 个按钮（纯记录/待办/进行中/已完成）+ 自定义状态 + 进度行，在 360px 下标签换行、按钮过窄（编辑器 460px 宽是 500px 视口时；360 时更挤）。
2. **排程三字段一行**：开始/结束/时长(分) 并排，360px 下极挤。
3. **进度行挤压**：caption + range + number + % 一行。
4. **头部拥挤**：emoji 瓦片 + 标题输入 + 日期 + 类型下拉 叠两行，窄栏下标题输入被压缩。
5. **弹窗尺寸**：500px 视口下 460×720（含 40px 顶距），body 滚动 550/522 略超。
6. 弹窗整体为宽屏设计，**未做窄栏断点适配**（侧栏 320–500 才是常态）。

交互现状（源码级）：
- `openEditor`（sidepanel.js:261）控制 overlay 显隐；overlay 有 `.hidden` 类切换。
- `.status-seg` 为 radiogroup（role）分段按钮；进度 range + number 双绑定。
- 排程：time×2 + duration number + 自动计算显示。
- 更多属性（details）默认折叠。

## Requirements（待用户确认方向后细化）

- R1. 弹窗在 320/360/400/500px 下均清晰可用：无横向滚动、无标签换行错位、控件触控目标合理。
- R2. 状态选择（分段）窄栏友好：换行不破版或改为等宽紧凑 chips。
- R3. 排程/进度/头部按窄栏重排（如多行、两列、分组）。
- R4. 交互打磨：弹窗可 Esc 关闭、Enter 保存（内容区外）、聚焦管理、aria 完善。
- R5. 遵循设计系统 token/组件规范；亮暗主题一致。
- R6. 用 dev-loop 回归（多宽度 + 断言 + 0 console error）验证。

## Acceptance Criteria

- [ ] 360/400/500px 截图核验：无挤压/无换行错位/层级清晰。
- [ ] 新建、编辑、类型切换、保存、取消全流程可用。
- [ ] 键盘：Esc 关闭、可 Tab 顺序合理、焦点可见。
- [ ] 亮暗主题一致；dev-loop 回归全绿 + 0 console error。
- [ ] 工作区干净、提交边界清晰可回退。

## Out of Scope

- 编辑器功能本身的新增（不改卡片字段体系）。
- 分步式/向导式大范式重构（除非用户明确选择）。
- 图标系统整体替换（与「SVG 图标系统」任务分轮）。

## Open Questions（规划期）

- （用户决策）重做方向：窄栏紧凑化重排（推荐）vs 分步式交互范式 vs 其他 —— 待用户确认。
