# 参考截图升级月视图

## Goal

将 Journal 的现有月历从“日期 + 卡片数量热力指示”升级为参考截图风格的月度任务工作台：用户能在整月网格中直接阅读任务、识别完成状态、切换月份，并通过日期与任务进入既有编辑/日程流程。

## Background / Confirmed Facts

- 项目是原生 JavaScript Chrome MV3 侧边栏，不使用框架。
- `extension/views/calendar.js` 已提供 6×7 日期网格、当前日/选中日、计数档位与键盘 roving tabindex。
- `extension/shared/model.js` 已提供 `getCardsByDate`、卡片状态和开始时间工具。
- `extension/entries/bind-views.js` 已绑定月历月份切换、今天按钮和日期点击。
- 当前侧栏月历与主区月视图是不同入口；本任务优先升级主区月视图，同时保持现有侧栏月历可用。
- 设计系统要求 320–500px 侧栏可用、状态不能只依赖颜色、交互元素必须可键盘操作、渲染函数幂等且不读写存储。

## Requirements

### R1. 月份工作台布局
- 主区月视图显示月份标题、上月/下月、本月操作。
- 显示周一至周日七列，完整月份固定 6 行 42 格；相邻月份日期保留但弱化。
- 今天、当前选中日期、周末和非本月日期有可区分但克制的视觉状态。

### R2. 日期任务展示
- 日期单元格直接显示当天卡片条目，而不是只显示数量。
- 每条条目显示状态图标、标题和开始时间（有时间时）。
- 标题过长省略，完整标题通过 `title`/可访问名称保留。
- 每个日期最多展示有限条目，超出时显示“更多”入口或数量，不撑破网格。
- 空白日期提供新建卡片入口；新卡片沿用现有卡片编辑器和日期字段。

### R3. 既有数据和交互复用
- 月视图从现有 repository/view-state 数据读取，不新增日历专用持久化模型。
- 点击任务打开既有卡片编辑器。
- 点击日期更新选中日期，并沿用现有日期导航行为。
- 月份切换、本月操作与其他视图的日期状态保持一致。
- 不破坏周视图、日程时间线、卡片池、热力图和侧栏月历。

### R4. 可访问性与响应式
- 月历网格保持语义 `role=grid`，日期和任务按钮可键盘访问。
- 状态同时使用图标/文字语义与颜色；焦点可见。
- 320、360、400、500px 宽度下不产生意外横向滚动；窄宽度下通过减少可见条目和省略标题降级。
- 支持 `prefers-reduced-motion`，本期不引入必要动画。

## Out of Scope

- 农历、节气、法定节假日和调休数据。
- 拖拽改日期、拖拽排序、拖边改时长。
- 新的数据模型、同步协议或 host API。
- 完全重做周视图、日程时间线和卡片池。
- 第一版复杂月份选择器与多日选择。

## Acceptance Criteria

- [ ] 主区月视图可稳定渲染 6×7 月历网格和月份导航。
- [ ] 月历日期单元格可直接显示卡片标题、状态和时间，并正确处理跨月日期。
- [ ] 今天、选中日、非本月日期和周末样式可区分。
- [ ] 点击任务、日期和新建入口均复用现有状态/编辑流程。
- [ ] 任务过多时单元格高度稳定，并提供可访问的更多提示。
- [ ] 现有月历、周历、时间线、卡片池和热力图回归通过。
- [ ] `cd extension && npm run lint`、`npm test` 和 UI 多宽度回归通过。
- [ ] 月历纯计算/渲染逻辑有覆盖日期边界、分组排序、状态和截断的测试。

## Assumptions

- 第一阶段优先参考截图的“信息密度和可读性”，而不是逐像素复制；项目侧栏窄宽度决定需要渐进降级。
- 默认沿用项目现有绿色设计 token，不引入截图中的多色状态编码。
