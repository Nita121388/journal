# 类型收敛（灵感并入文本）+ 卡片池类型筛选（待办 = 任务视图）

## Goal

把卡片类型从「文本 / 任务 / 灵感」收敛为「文本 / 任务」两种；灵感在**显示层**并入文本
（数据零迁移、后端与同步零改动）。同时在卡片池新增**类型筛选**（全部 / 文本 / 任务=待办），
让"卡片池里能看到待办"落地，并理顺「任务 = 待办」的心智。

## 背景与当前事实

- 卡片 `type` 实际只有三值：`text` / `task` / `idea`。
- **「待办」不是一种类型**，而是 `type === 'task'` 卡片在侧栏的视图
  （`getTodos()` 只筛 `type==='task'`）。任务与待办是同一件事的两种叫法。
- **灵感与文本结构完全相同**（都无 `done`/`priority` 语义差异），仅是标签区分，重叠度高。
- 后端 `host/lib/storage.js` 与 `host/sync/merge.js` 的类型白名单含 `idea`；
  存量 idea 卡片已存在于 SQLite / 同步介质中。

## Requirements

1. **新建/编辑不再产生 idea 类型**
   - 编辑器类型下拉移除「💡 灵感」选项，只留「📝 文本」「☑️ 任务」。
   - 卡片 footer 的「🔄 切换类型」循环改为 `text ↔ task`（无 idea 档）。
2. **存量 idea 卡片显示层归入文本（零数据迁移）**
   - 保留 `typeIcon('idea')` 回落为 📝、月/周历 `type-idea` 摘要色并入 `type-text`、
     `getCardTypeCounts` 不再单列 idea 计数（idea 计入 text）。
   - 数据层/host/同步**不改**：`type: 'idea'` 仍可被 host 正常读写与 LWW 合并，
     跨端同步不丢数据，符合"零丢失历史数据"原则。
3. **卡片池新增类型筛选**
   - 在卡片池顶部加类型筛选条：`全部 / 文本 / 任务`（任务项标注"待办"含义）。
   - 类型筛选与既有**标签筛选**并存（AND 生效）：`类型=任务 且 标签=X`。
   - 选中"任务"即等价于"在卡片池看未完成待办"。
4. **待办区块保持现状**
   - 侧栏「📝 待办」区块继续作为 `type==='task'` 视图（勾选完成 / 优先级 / 截止日 /
     未完成-全部-已完成筛选），不因本次收敛改变行为。

## Acceptance Criteria

- [ ] 编辑器类型下拉只有「文本 / 任务」两项；新建卡片默认为文本。
- [ ] footer「🔄」在 文本↔任务 间来回切换，不出现灵感。
- [ ] 存量 idea 卡片在时间线 / 月历 / 周历 / 卡片池均以 📝 文本样式显示，不再出现 💡；
        刷新、host 重启、触发一次同步后 idea 卡片**仍在且内容不变**（零丢失）。
- [ ] 卡片池出现类型筛选：全部 / 文本 / 任务；点"任务"只显示 task 卡片；
        与标签筛选可叠加（类型+标签同时生效）。
- [ ] 侧栏待办区块行为与改动前一致（勾选、删除、过滤、统计）。
- [ ] host 测试 `cd host && npm test` 全绿（本次不改 host，应无回归）。

## Notes

  （仅计数口径），不改 host。
- 「灵感」不做物理数据迁移；如未来需彻底清理可在数据同步引擎任务里做一次性迁移。
