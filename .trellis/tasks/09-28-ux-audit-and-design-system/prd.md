# 子任务2：UX 审计 + 设计系统文档

> 父任务：`09-28-agent-driven-extension-ux-polish`
> 方法论文档：`../research/ux-design-methodology.md`（规划期底稿）
> 交付方式（用户已确认）：**文档先行，用户确认后再动产品代码**。

## Goal

以资深产品经理视角，对 Journal 做**完整 UX 审计**并产出**设计系统文档**，为后续落地改造（子任务3 及以后各轮）提供决策依据与规范底座。审计要建立在**真实渲染证据**上（利用子任务1的闭环截图，不再靠肉眼/纸面）。

## Background / Confirmed Facts

- 产品形态与现有 UI 结构：见父任务 PRD §Background（sidepanel 三栏布局、卡片池/日历/热力图/技能面板、时间线三视图、卡片体系）。
- **已采集的真实渲染证据**（规划期，360px 截图）：
  1. 信息架构倒置：次要面板（卡片池/日历/热力图）占满首屏，主工作区「日程」在折叠线以下（y≈790/800）。
  2. 卡片池筛选 chips 三行堆叠、视觉杂乱；「没有符合条件的卡片」空状态与计数 0 并存。
  3. 时间线 08:00–13:00 大面积空白，无效占用。
  4. 热力图几乎全灰、信息密度低。
  5. 图标全部 emoji（📓⚙️🃏🗂📅🔥🧠⏱），无图标系统、跨平台渲染不一致。
- 代码事实：`sidepanel.css` 已有 29 个 CSS 变量 + `[data-theme="dark"]` 暗色模式（JS 切换，CSS 无 `prefers-color-scheme` 兜底）；硬编码 hex 79 处、`!important` 8 处、JS 内联 style 22 处（token 渗透不彻底）。
- 可访问性现状：HTML 有 32 处 aria + 5 处 role；CSS 有 focus-visible 12/:focus 23/outline 21；**无 `prefers-reduced-motion`、无 `tabindex`/roving、无 `sr-only`**。
- 交互：无视觉反馈面（loading/skeleton/乐观更新）覆盖证据待审计补全。

## Requirements

- R1. **UX 审计报告**（`docs/ux-audit.md` 或任务 research/ 下，落仓库 docs/）覆盖 ≥6 维度，每条结论附证据锚点（file:line 或截图路径）：
  1. 产品定位与信息架构（IA）
  2. 视觉层级与一致性（含 token 渗透审计）
  3. 交互流程（写日志/打卡/TODO/AI 主路径、编辑/新建/筛选/视图切换）
  4. 状态设计（空/加载/错误/成功反馈）
  5. 可访问性（对照 WCAG 2.2 AA 关键准则）
  6. 可发现性与可学习性
  7. 暗色模式与主题一致性
  8. 响应式/侧栏多宽度（320/360/400/500）
- R2. 每条审计结论标注**严重度（P0 阻断 / P1 高 / P2 中 / P3 低）**与**建议方向**，输出按优先级排序的**改造清单**（供子任务3执行）。
- R3. **设计系统文档**（落 `.trellis/spec/frontend/design-system.md` 供后续复用）：
  - 设计 token 三层（基础→语义→组件）：色板（含暗色）、字体/字号/行高、间距、圆角、阴影、动效时长与缓动（含 `prefers-reduced-motion`）、z-index。
  - 组件规范：卡片/按钮/标签/筛选 chips/空状态/图标（含 emoji 分级策略，如「功能图标用 SVG、情感用 emoji」）。
  - 可访问性规范：焦点环、对比度（≥4.5:1 正文）、键盘导航、ARIA 约定。
  - 与现有 29 个 CSS 变量**映射与迁移说明**（不推倒重来，逐步收敛硬编码 hex）。
- R4. 产出**改造优先级清单**，至少 ≥5 项 P1/P2 级可落地项（供子任务3第一轮执行）。
